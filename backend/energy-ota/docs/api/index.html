API Reference
  • 1.通用存活探针：所有依赖 energy-common 的 Servlet 服务自动获得 /ping。 用于网关连通性与健康检查（Phase 3 起）。
    • 1.1.存活探针：返回服务名、版本与当前时间，供网关/负载均衡做连通性与健康检查。
  • 2.OTA 批次任务 API（网关路由 /api/ota/** → energy-ota）。

    &lt;ul&gt;
    &lt;li&gt;POST /api/ota/tasks 创建批次任务（设备快照 + 立即开始）；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/tasks 任务分页；GET /api/ota/tasks/{taskId} 任务详情；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/tasks/{taskId}/devices 设备明细分页；&lt;/li&gt;
    &lt;li&gt;POST /api/ota/tasks/{taskId}/start 立即开始；POST /api/ota/tasks/{taskId}/pause 暂停； POST
    /api/ota/tasks/{taskId}/resume 恢复；POST /api/ota/tasks/{taskId}/gray/advance 推进灰度； POST
    /api/ota/tasks/{taskId}/cancel 取消；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/tasks/{taskId}/statistics 成功率/统计。&lt;/li&gt;
    &lt;/ul&gt;
    • 2.1.创建 OTA 批次升级任务（拍摄目标设备快照并写入任务与设备明细）。

      若请求未指定 planTime（scheduleTime 为 NULL），则创建后立即开始执行。
    • 2.2.批次任务分页查询，支持按任务名、状态筛选。
    • 2.3.查询单个批次任务详情。
    • 2.4.查询批次任务下的设备升级明细分页，可按设备状态筛选。
    • 2.5.立即开始执行批次任务（向目标设备下发升级指令）。
    • 2.6.暂停执行中的批次任务（已下发的设备继续当前流程，新设备停止下发）。
    • 2.7.恢复已暂停的批次任务，继续向剩余设备下发升级。
    • 2.8.推进灰度批次任务到下一灰度批次（按比例扩大设备覆盖范围）。
    • 2.9.取消批次任务（终止剩余设备下发，已成功设备不受影响）。
    • 2.10.统计批次任务成功率及设备状态分布（基于任务与设备明细聚合）。
  • 3.OTA 升级包 API（网关路由 /api/ota/** → energy-ota）。

    &lt;ul&gt;
    &lt;li&gt;POST /api/ota/packages 上传升级包（multipart，自动 RSA 签名）；&lt;/li&gt;
    &lt;li&gt;POST /api/ota/packages/{packageId}/diff 平台生成差分包（S5-1）；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/packages/{packageId}/verify-signature 验签（文件 SHA256 + RSA 签名）；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/packages/{packageId}/url 生成签名下载 URL；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/packages 升级包分页查询；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/packages/{packageId} 升级包详情；&lt;/li&gt;
    &lt;li&gt;PUT /api/ota/packages/{packageId}/status 更新升级包状态（启用/停用）；&lt;/li&gt;
    &lt;li&gt;DELETE /api/ota/packages/{packageId} 删除升级包；&lt;/li&gt;
    &lt;li&gt;GET /api/ota/files/** 升级包文件下载——签名 URL 校验（S5-4）+ HTTP Range 分片/断点续传（206 Partial
    Content）。&lt;/li&gt;
    &lt;/ul&gt;
    • 3.1.上传升级包（multipart/form-data，包含固件文件与元数据），服务端自动计算文件摘要（MD5/SHA256）并生成 RSA 签名。
    • 3.2.平台基于两个全量包生成差分包（basePackageId 为源全量包，packageId 为目标全量包）。

      当差分无收益时退化为全量下发，此时 diffPackageId 返回空字符串并提示“差分无收益，已退化为全量下发”。
    • 3.3.校验升级包文件完整性：比对文件 SHA256 与平台 RSA 签名是否可用公钥验签通过。
    • 3.4.为指定升级包预生成带时效的 HMAC-SHA256 签名下载 URL（供管理端或下发信封使用）。
    • 3.5.升级包分页查询，支持按产品、版本、包类型、状态筛选。
    • 3.6.查询单个升级包详情。
    • 3.7.更新升级包状态（启用/停用）。
    • 3.8.删除升级包（软删除，置 deleted 标记）。
    • 3.9.升级包文件下载——双模式鉴权 + HTTP Range 分片/断点续传。
      路径：/api/ota/files/{productKey}/{version}/{module}/{fileName}[?expires=&sign=]
      <ul>
      <li>设备/信封模式：携带合法 {@code expires+sign} 签名 URL（S5-4），无需登录；过期/篡改 → 403；</li>
      <li>管理端模式：无签名参数时要求合法登录态 JWT（与网关同源验签），未登录/无效 → 401；</li>
      <li>带 Range 头 → 206 Partial Content（分片断点续传，块大小 segmentSize）；</li>
      <li>普通 GET → 200 全量。</li>
      </ul>
