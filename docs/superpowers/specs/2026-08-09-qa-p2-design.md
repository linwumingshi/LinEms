## 4. 分项设计

### 4.1 strategyConfig.ts —— ID2 契约变更

`parsePeakValleyConfig` **删除** `chargeWindows.length === 0 && dischargeWindows.length === 0` 分支（`:76-78`）。契约：**结构校验只保证窗口字段合法，不要求至少一个窗口**；「≥1 窗口」移到保存闸。空窗口数组 → `{ ok: true, config: {chargeWindows:[], dischargeWindows:[]}, rest }`，JSON↔结构化可往返。

新增（保存闸，供 EmsStrategy.save 用）：

```ts
/** 保存闸：结构校验（validatePeakValleyConfig）+ 至少一个窗口。空配置 = 无窗口。 */
export function validatePeakValleySaveable(config: string): string[] {
  if (!config.trim()) return ['请至少配置一个充电或放电窗口'] // 空配置 ≠ 非法 JSON，先给「至少一个窗口」
  const issues = validatePeakValleyConfig(config)
  if (issues.length) return issues
  const parsed = parseJsonConfig(config)
  const obj = parsed.value as { chargeWindows?: unknown[]; dischargeWindows?: unknown[] }
  if ((obj.chargeWindows?.length ?? 0) === 0 && (obj.dischargeWindows?.length ?? 0) === 0) {
    return ['请至少配置一个充电或放电窗口']
  }
  return []
}
```

**单测更新（strategyConfig.spec.ts）**：
- `:62-66`「至少一个窗口」→ 改为断言 `parsePeakValleyConfig({chargeWindows:[],dischargeWindows:[]}).ok === true`。
- `:78` `validatePeakValleyConfig('{"chargeWindows":[],"dischargeWindows":[]}')` → `[]`。
- 新增：`validatePeakValleySaveable('')` → `['请至少配置一个充电或放电窗口']`（空配置不进 JSON 解析）；`validatePeakValleySaveable('{"chargeWindows":[],"dischargeWindows":[]}')` → `['请至少配置一个充电或放电窗口']`；`validatePeakValleySaveable(validConfig)` → `[]`；空窗口序列化后往返解析 ok。

### 4.3 utils/planGate.ts —— ID4 预检（纯函数 + 查询封装）

```ts
/**
 * 计划生成前置：安全约束就绪预检。
 * 后端契约：EmsPlanService 仅要求 constraint 行存在（缺失抛「未配置安全约束」）；
 * SafetyEnvelopeValidator 对 socMin/socMax/chargePowerMax/dischargePowerMax 取 doubleValue()（null→NPE）。
 * 前端预检与后端闸对齐：行存在 + 4 字段非空。
 */
import { emsApi } from '@/api/ems'
import type { EmsConstraint } from '@/types/models'

/** 约束是否满足生成计划的必要条件（行存在 + 4 字段非空） */
export function hasFullConstraint(c: EmsConstraint | null | undefined): boolean {
  if (!c) return false
  return c.socMin != null && c.socMax != null && c.chargePowerMax != null && c.dischargePowerMax != null
}

/** 查询该站约束；查询失败/缺行 → null（不抛，由调用方决定提示） */
export async function ensureConstraint(stationId: string): Promise<EmsConstraint | null> {
  try { return await emsApi.constraintGet(stationId) } catch { return null }
}

/** 预检便捷入口：true = 就绪 */
export async function constraintReady(stationId: string): Promise<boolean> {
  return hasFullConstraint(await ensureConstraint(stationId))
}
```

统一提示文案（调用方）：`该电站安全约束未就绪（未配置或 SOC/功率上下限缺失），无法生成计划`（`ElMessage.warning`，属领域前置条件而非字段校验，保留 toast）。

**单测（planGate.spec.ts，mock `@/api/ems`）**：
- `hasFullConstraint`：null / 4 字段任一 null → false；全非空 → true。
- `ensureConstraint`：resolve 行 → 返回行；reject → null。
- `constraintReady`：齐全行 → true；null → false。

## 5. 数据流

- **策略页**：保存前置内联校验（errs）→ 通过后走既有 DTO payload → API；`generatePlan` 预检 `constraintReady` → 通过后 `planGenerate`。
- **计划页**：生成弹窗内联校验 → `constraintReady` 预检 → `planGenerate`；`renderChart` 渲染后 tooltip/grid 展示修复。
- **Device 页**：`loadStations()`（P1 共享缓存，与策略/计划页同源）填电站下拉；选产品 → `narrowedTypes` 收敛设备类型并回填；保存内联校验。
- **名称回退**：任何 id 查不到 → `stationName` 回退裸 id，绝不空白。

## 6. 错误处理

- 校验错误（字段缺失/格式）→ 输入框下内联红字（`:error`），禁 Toast（11-b）。
- 领域前置条件（约束未就绪）→ `ElMessage.warning` 一次性提示，不吞后端错误。
- API 失败（网络/4xx/5xx）→ 既有 `ElMessage.error` 透传，不变。
- `loadStations()` 失败：Device 页静默回退裸 id（与 P1 `loadMaps` 静默 catch 一致）。
